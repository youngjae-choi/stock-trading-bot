# 시황 단일출처 전환 (index-board) — 기획서 v0.1

> PM 결정(2026-06-25): **모든 시황 데이터는 index-board에서 가져온다. 우리 자체 LLM 시황분석은 폐기한다.**
> 근거: index-board는 AI로 장전·장중 시황을 숫자까지 정리해 발행하며 우리보다 정리 품질이 높다. 우리가 별도 LLM로 재분석하는 건 비용·불안정·중복이다.

## 왜 필요한가 (WHY)
- 우리 봇은 시황을 자주 **잘못 분석해 잘못된 regime을 할당**한다. 실측 사례: 6/19 tone=positive→실제 하락, 6/23 neutral→-9.3% 폭락, 6/24 negative→+3.71% 급등. market_tone confidence가 자주 0.0.
- 잘못된 regime은 장세 대응(진입 공격성·사이징·방어)을 통째로 어긋나게 한다.
- index-board는 동일 시황을 **AI로 장전·장중 정리 + 숫자 포함**(VIX·공포탐욕·코스피200 선물갭·USD/KRW·필라델피아 반도체·외국인 수급)해 발행. 10일 아카이브, 날짜→시간 카드.
- 현재 우리는 index-board의 **프로즈만 키워드 카운팅**할 뿐 숫자를 안 쓰고, 장중 타입(`regular`)을 못 잡아 **장중엔 불안정한 Opus LLM로 폴백** 중. → 중복·비용·오판.

## BETTER 제안 (PM이 말한 것보다 나은 방향)
"LLM 끄고 index-board만"의 단순 적용을 넘어, 신뢰성·안전을 위해 4가지를 함께:
1. **장중 타입 버그 수정**(`post`→`regular` 등 실제 발행 타입 매핑) — 장중 브리핑 수신 자체를 복구
2. **숫자 파서** — 브리핑 텍스트에서 VIX·공포탐욕·선물갭·환율·외국인수급을 구조화 → 객관 regime 신호
3. **폴링 + 변경감지** — 장중 1~2분 폴링, `generatedAt` 변경 시 즉시 regime 재평가 (push 불필요: 하루 몇 회 발행 소스라 폴링으로 사실상 실시간. push는 헤드리스 서버에 fragile)
4. **안전 분리 원칙** — regime은 **advisory**(진입 공격성·사이징·방어 조절)일 뿐, **하드 리스크가드(손절·긴급정지·일일손실한도)는 외부소스에 의존 금지**. index-board 장애 시에도 손절은 독립 작동.

## 사용자 UX 흐름 (데이터 흐름 / 운영자 관점)
1. **장전(08:00경)**: index-board `장전(pre/kospi)` 브리핑 스크래핑 → 숫자 파싱 + 서술 → regime·risk_level 산출 → `market_tone_results` 저장. **Opus 호출 없음.**
2. **장중(09:00~15:20, 1~2분 폴링)**: `장중(regular)` 최신 카드 감시 → `generatedAt` 변경 시 regime 재평가 → 바뀌면 intraday_regime_monitor에 반영(SET 전환 등 기존 경로).
3. **장후/야간**: `장중·장후` 나스닥 브리핑 → 다음날 장전 context.
4. **콘솔 표시**: 시황 카드에 index-board 원문 + 파싱된 숫자(VIX/공포탐욕/선물갭) + 우리 regime 라벨 + 출처/생성시각 표기.
5. **엔진 소비**: regime → 진입 공격성·사이징·방어 강도(장세 플레이북, 별도 기획과 연계).

## 화면/모드별 동작
- **모의/실 계좌 공통**: 시황 출처는 index-board 동일.
- **정상**: 최신 generatedAt 기준 regime + 숫자 표시, "출처: index-board, HH:MM 생성".
- **장애/스테일**: 마지막 정상 regime 유지 + "⚠️ 시황 갱신 지연(스테일)" 배지, 엔진은 직전 regime 보수적 사용.
- **파싱 실패**: 숫자 없이 서술 기반 regime만 + 경고 로그/알림.

## 상태별 UI & 메시지 문구
- 성공: "시황 갱신됨 — {regime} (VIX {x}, 공포탐욕 {y}, 선물 {z}%) · index-board {HH:MM}"
- 폴링 무변화: (조용히 무시, 로그만)
- 스테일(>N분 갱신없음): "⚠️ 시황 갱신 지연 — 마지막 {HH:MM} 기준 유지"
- 장애(스크래핑 실패): "🔴 시황 소스 연결 실패 — 직전 regime 보수 적용, 신규 진입 신중"
- 구조변경 감지(타입/포맷 깨짐): "🔴 시황 파싱 실패 — 수동 확인 필요" + 운영 알림

## 엣지케이스 & 예외처리
- **index-board 다운/타임아웃**: 직전 regime 유지(스테일 표시), **우리 LLM 부활 안 함**, 보수적 모드 + 알림. (단, 완전 무신호 장기화 시 PM 정책 필요 — 검토요청 1)
- **사이트 구조 변경**(오늘 발견한 `post`→`regular` 류): 파싱 회복력 + "구조변경 의심" 알림. 타입은 화이트리스트가 아니라 발견형으로.
- **스테일 데이터**: `generatedAt`이 오래됐는데 최신처럼 쓰지 않기 — 신선도 임계(예: 장중 N분) 초과 시 스테일 처리.
- **숫자 포맷 변동**(단위·천단위 콤마·범위표기): 정규식 다중 패턴 + 실패 시 서술 폴백.
- **법적/ToS**: 사이트 면책("정확성·실시간성 보장 안 함") 명시 → regime은 advisory로만, 매매 안전장치는 독립. 스크래핑 예의(폴링 주기·UA).
- **이중 출처 충돌**: VIX·환율 등을 KIS/overnight에서도 받던 부분 — 시황 맥락은 index-board 단일화, KIS는 체결·잔고·실시간 가격 등 거래데이터 전담으로 역할 분리(검토요청 2).

## 기술 구현 힌트
- `index_board_scraper.py`: 타입 매핑 수정(`pre`/`regular`/(있으면)`post`), `select_latest` 보정, 숫자 추출 헬퍼 추가.
- `market_tone.py`: **Opus 경로 제거/비활성**(0805_opus_market_tone.md·intraday_market_tone.md 호출 폐기), index-board 파싱 결과를 regime·risk_level의 단일 입력으로. 휴리스틱은 서술→regime 보강용으로만 유지.
- 스케줄러: 장중 `job_intraday_refresh` 폴링 주기 단축 + generatedAt 변경감지 트리거.
- 저장: `market_tone_results`에 파싱 숫자 컬럼(또는 JSON) 추가, provider='index-board' 고정.
- regime→행동 연결은 **장세 플레이북 기획**과 합류(여기선 시황 입력까지).

## PM 확정 결정 (2026-06-25)
1. **장기 장애 시 정책 + LLM 처리(1·5 통합)**: 기존 LLM 시황로직을 **휴면 백업으로 보존**(삭제 X). 평소엔 완전 비활성, **index-board 장애/장기 무신호 시 백업 프로세스 자동 활성**해 regime 산출(복구 시 자동 복귀). provider 태깅으로 구분.
2. **숫자 출처 일원화**: ✅ **전부 index-board로**. KIS/overnight 시황숫자 경로는 regime 입력에서 제외. KIS는 체결·잔고·실시간가격 등 거래데이터 전담.
3. **폴링 주기**: ✅ **장중 2분**.

5. → 1번에 통합(휴면 백업 보존, 평소 비활성, 장애 시 활성).
