# 6엔진 구조 재편 — 개발계획서 v0.1 (2026-08-21)

## 원본 요구사항 (PM 발화 그대로)
> 우리에게 필요한건 시장감지&감시, 전략설정, 종목선정, 매수감시, 매도감시, 매매.. 이건데 각각 여기 저기 흩어져 있음 안돼, 정확하게 각각의 엔진으로 존재해야 하고 그 엔진의 내용은 설정에서 관리자가 수정할 수 있어야 해 그래야 나중에 전략에 대한 변경이 용이하도록.. 같은 내용들이 여기조금 저기 조금 혹은 하드코딩등으로 숨어있다면 찾아내서 엔진화를 시켜야함.
>
> 결정1 점진적 / 결정2 (가)설정레벨 먼저→최종 (나)UI까지 / 결정3 통합 + **시장분위기가 판단되면 우리가 가진 전략 중 하나를 꺼내쓰는 형태(시장분위기별 전략 존재)** / 결정4 종목수 아닌 **예수금 투입비중** 중요(알아서 판단) / 결정5 설정화 + **VIX·KOSPI(+지표) 결정론, AI 개입 없는 순수 Daytrading**

## 핵심 컨셉 — "레짐 → 플레이북"
시장분위기(레짐)를 판단하면 그에 대응하는 **전략 플레이북**을 자동으로 꺼내 쓴다.
플레이북 = 그 장세에서의 {종목선정·매수게이트·매도·사이징} 파라미터 한 벌.
이게 결정3(통합)의 실체이자, 5장세 프레임워크(폭락/하락/보합/상승/폭등+전환)의 구현체다.

## 목표 아키텍처 — 6개 엔진

```
        ┌──────────────────────────────────────────────┐
        │  ① 전략설정 엔진 (단일 권위 · 관리자 수정)      │
        │  레짐별 플레이북 N개 = {선정·매수·매도·사이징}   │
        └───────────────┬──────────────────────────────┘
   현재 레짐 판단 ↓ pull │ 플레이북 제공 ↑ read
        ┌───────────────┴──────────────────────────────┐
        │ ② 시장감지  → ③ 종목선정 → ④ 매수감시          │
        │                          → ⑤ 매도감시 → ⑥ 매매 │
        └──────────────────────────────────────────────┘
```

| 엔진 | 책임 | 현재 흩어진 곳 → 목표 |
|---|---|---|
| ① 전략설정 | 레짐별 플레이북 단일 권위 | system_settings+RulePack+레짐SET+코드기본 **4중 → 1** |
| ② 시장감지 | VIX·KOSPI+선행지표 결정론 판단, 30분틱, 전환감지 | market_tone·intraday_regime_monitor·index_board **분산, 임계 하드코딩 → 통합·설정화** |
| ③ 종목선정 | 플레이북 선정 params로 유니버스/스크리닝 | universe_filter·hybrid_screening·intraday_profile |
| ④ 매수감시 | 플레이북 매수게이트로 진입 판단 | **decision_engine(2193줄)에 매몰 → 분리** |
| ⑤ 매도감시 | 플레이북 매도 params(손절·익절·트레일·수확) | position_manager·eod_liquidation |
| ⑥ 매매 | **예수금비중 사이징** + 주문/체결 | order_executor·daily_capital·exploration_gate·order_preflight **사이징 4곳 분산 → 통합** |

## 단계 로드맵 (점진적 — 결정1)
1. **Phase 1 전략설정 엔진** ← 뿌리(충돌·하드코딩의 근원). 상세 아래.
2. **Phase 2 시장감지 엔진** — 장중도 선행지표 결정론 판단 + 전환감지(하락/상승) + 임계 설정화.
3. **Phase 3 종목선정 / Phase 4 매수감시** — decision_engine 2193줄 분해.
4. **Phase 5 매도감시 / Phase 6 매매** — 사이징 통합·주문 정리.
5. **Phase 7 관리자 UI** — 엔진별 설정 화면(결정2의 최종 (나)).

각 Phase: 무손실 이관 → STRATEGY_SPEC 드리프트 0 유지 → shadow(동작불변 확인) → 회귀테스트 → 재기동 배포.

## Phase 1 상세 — 전략설정 엔진 (플레이북 권위)

### 구현 범위
- [ ] **1a. 플레이북 스키마** 정의: 레짐(폭락/하락/보합/상승/폭등/하락전환/상승전환)별 {선정·매수게이트·매도·사이징} 전체 파라미터 한 벌.
- [ ] **1b. 단일 저장소·resolver**: `get_playbook(regime)` — 소비 엔진이 흩어진 소스 대신 이 하나만 읽는다. (기존 `regime_sets` 테이블 확장 재사용 검토)
- [ ] **1c. 무손실 초기화**: 현재 라이브 값(STRATEGY_SPEC 실측 57레버)으로 플레이북을 채워 **동작 불변** 보장.
- [ ] **1d. 예수금비중 사이징 전환(결정4)**: `baseline*budget_rate/max_positions` → **`deposit × per_position_rate`(종목당 비중) + `deploy_target_rate`(총 배포 상한)** 로. 종목수는 결과(파생)일 뿐 divisor 아님.
- [ ] **1e. 하드코딩 승격(결정5)**: 레짐 임계(vix>28/22·kospi±1.5/0.5)·체결강도 55%·스케일아웃 구간을 플레이북/전역 설정으로.
- [ ] **1f. max_positions 단일화**: 3출처(5/12/10) → 플레이북 1값. order_preflight도 플레이북 참조. (결정4 반영 — count는 배포비중의 파생 상한)

### 추가 제안 (PM 승인 필요)
- **A. 플레이북 초기값 = 현재값 그대로**(무손실). 값 튜닝(전략 개선)은 구조 완성 후 별도. → 리스크 최소.
